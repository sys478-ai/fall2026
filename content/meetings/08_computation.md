## Topic / Focus

How do input, memory, instructions, and a processor work together to turn information into action? The goal is a mental model of computation you can later compare with machine learning, not computer architecture.

Last class asked how the world becomes data. Today asks what happens to that data once it is inside the machine. Sept. 15 asks what changes when we cannot write the procedure explicitly.

## Guiding Questions

- What actually happens inside a computer when you click a button?
- Why can the same machine do many different things?
- What is easy when the rules are explicit, and what becomes hard when they are not?

## In This Class

In this meeting, we will:

- sketch what happens on a click, then map input, memory, processor, output, and storage: the machine repeatedly executes stored instructions on represented information
- use fetch → decode → execute (LOAD / ADD / STORE) as a short physical activity, then a thermostat-style IF/ELSE to ask where the rule and the threshold came from
- keep logic gates to one slide, reconnect sound → numbers → memory → instructions → output, and analyze course registration as an explicit procedure that is algorithmic but not AI

## Closing Reflection

What is one thing a traditional computer can do very well when the rules are explicit – and one thing that becomes difficult when the rules are hard to specify?
